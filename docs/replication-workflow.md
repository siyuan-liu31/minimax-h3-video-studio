# 复刻工作流设计

本模块借鉴 Hypit 的“分析、审阅、构建、恢复”工作方式，执行层仍是原生 H3 分段生成。
当前完成的是可审阅、可恢复的工作台；切点检测不等于理解剧情、口播文案或字幕。

## 数据与 CLI

唯一持久对象是服务端 VideoProject，附带 `h3.replication/v1` recipe。前端、CLI 和 Agent
操作使用同一 HTTP API，不各自保留一套执行状态。规划结果包含初始意图、素材哈希、
分窗、连续性、音频策略与逐段请求；recipe 的初始 prompt hash 记录编译来源，执行以
每段 `request.prompt` 为准。

| 阶段 | CLI | 行为 |
| --- | --- | --- |
| 规划 | `replication plan` | 解析/上传资源，输出方案；不生成 |
| 保存 | `replication create --plan` | 校验并保存草稿；不生成 |
| 审阅 | `list / inspect / export` | 检查真实持久状态；导出不带运行结果 |
| 修改 | `edit-segment` | 修改 prompt/steps/seed，校验读取时版本 |
| 执行 | `run / wait / stop / rerun` | 复用 project 执行器与依赖规则 |
| 交付 | `merge / download / resume` | 复用已完成结果，合并并原子下载 |

一键 `video replicate` 保留兼容，适合无需中途审阅的任务。Agent 用 operation registry
发现机器可读 schema，不依赖解析 help 文本。导出的方案引用当前服务器素材 ID，不是
包含媒体的跨服务器项目包。

逐段 PATCH 只允许 `prompt`、`steps`、`seed`，必须带 `expected_updated_at`。同一把
服务端锁保护版本检查和更新，避免两个编辑器互相覆盖。已完成结果的失效范围是当前段
加上直到下一个独立段之前的连续依赖；合并结果同时失效。相同内容保存不清除结果。
活动项目拒绝编辑。来源范围、分窗、模型输出尺寸等结构修改仍走完整项目校验。

## 前端工作台

- 素材与方案：选择来源、意图、保留项、替换图、可用 Ref2VA Profile 与音频/连续性。
  先检测切点，再生成方案；展示摘要与编译提示词，保存草稿后进入审阅。
- 分段审阅：左侧分页列表，右侧来源/生成对照和提示词编辑；展示完成进度、错误与
  重跑影响范围。未保存时禁用切换项目和提交生成。保存使用开始编辑时的项目版本，
  外部修改后明确报冲突，用户可撤销本地修改读取最新文本。
- 成片：完成所有分段后显式合并，预览和下载。失败后用原项目继续，不重新规划。
- 刷新恢复：localStorage 只记选中 ID；项目定义与进度来自服务器。ID 必须存在于当前
  服务器列表。跳转长视频编辑器传入确切 ID，编辑器保存必须保留 recipe。
- 长素材：列表每页 20 段，避免一次渲染上千个视频；模型单段上限不变，总时长不固定限制。
  大项目的完整 JSON 读取/轮询仍有开销，后续可增加摘要列表和增量状态 API。

## 后续与 Hypit 接近所需的能力

1. 独立的分析产物：镜头语义、对白转录、说话人、逐字时间戳、画面文字；保留用户审阅
   与证据来源，不能把 ffmpeg 切点包装为视频理解。
2. 可编辑成片合同：字幕、B-roll、图形、旁白、音乐与视频轨道，明确时间坐标和组件版本。
   H3 视频段作为素材进入合成，而不是所有改动都重新生成视频。
3. 显式构建记录：依赖摘要、模型/Profile 身份、输入哈希、组件版本与产物哈希；复用条件
   可检查，分别重建字幕/声音/画面。

这些能力当前没有伪造按钮或返回值；本轮先把 CLI/前端共同依赖的项目生命周期做实。
